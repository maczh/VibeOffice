# 20: Web-wide legacy brand name cleanup

**What to build:** Remove product-brand uses of Quire, Ledger, and Lectern from the web source, package metadata, routes, storage namespaces, clipboard protocols, user-facing strings, documentation, tests, and generated assets; use Wordx, Excelx, and PPTX consistently.

**Blocked by:** 17: Wordx full module migration and naming; 18: Excelx full module migration and naming; 19: PPTX full module migration and naming.

**Status:** in-progress

**Progress:** React package and suite runtime routes now use `/wordx/`, `/excelx/`, and `/pptx/`; the Vite adapter maps those routes to the still-legacy engine source directories internally. The React build transforms its PWA shortcuts and screenshot paths to the new route/product names without changing the still-live classic public manifest. Standalone outputs are cleaned before emitting only their new routes. Excelx/PPTX private clipboard protocols now emit `excelx-clip` and `application/x-pptx`; their legacy names are asserted only by regressions that ensure those retired identifiers are absent at runtime. Legacy source folder names and many classic app identifiers/strings remain, so the repository-wide brand audit is not complete.

## Acceptance

- [ ] A case-insensitive repository audit finds no old product names in web-owned source, UI strings, paths, docs, tests, or generated web outputs.
- [ ] Old product-name references remain only where needed to identify historical source provenance or documented migration history, and those exceptions are narrowly listed.
- [ ] Microsoft product names, standards terminology, OOXML namespaces, and format-extension names are unchanged.
- [ ] Desktop/Tauri files remain untouched.
- [ ] Routes, persistence keys, template identifiers, MIME protocols, standalone app launch, and suite launch agree on the new names.
- [ ] Full tests, package builds, and `git diff --check` pass.

## Remaining compatibility references

These old names are still present but are not current React product identities. They remain explicitly in scope for eventual removal unless doing so would change the separately excluded desktop app:

- `public/quire/`, `public/ledger/`, and `public/lectern/` are still the classic source/runtime folders consumed by the Vite asset adapter.
- `tools/vite/legacy-runtime.mjs` maps the new package routes and output folders to those old source folders.
- `public/common/suite.js` retains the old IDs and paths for classic web and native desktop launches; React-host routing normalizes to the new IDs.
- The legacy app modules retain the old IDs only in non-React branches for their existing classic/native launch contracts; React-host New, template, attachment, and navigation calls use `wordx`, `excelx`, and `pptx`.
- `docs/react-packages.md` and source-module inventories name the old paths to document which legacy modules remain unmigrated.
- `tests/vite/workspace-packages.test.mjs` uses old-key template fixtures to verify that generated React metadata is transformed to the new routes.

Anything outside these compatibility, migration-inventory, or historical-test contexts is a brand-cleanup candidate.
