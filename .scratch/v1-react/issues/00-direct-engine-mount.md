# 00: Direct editor-engine mount foundation

**What to build:** Replace the iframe-based React adapters for Quire, Ledger, and Lectern with explicit same-document mount/dispose APIs that render inside React-owned host containers.

**Blocked by:** None. This is a prerequisite for editor package and suite completion.

**Status:** in-progress

**Architecture decision:** No iframe, nested browsing context, hidden iframe fallback, or cross-window postMessage bridge may remain in the React package/suite runtime. Keep the existing JavaScript document models, file-format readers/writers, calculation engines, and user-visible editing behavior. Refactor their bootstraps, DOM ownership, selectors, CSS boundaries, events, and lifecycle as required.

**Implementation notes:** The three current `A.init()` functions auto-run from classic scripts, query fixed IDs through `L.$`, and use the shared `window.L` namespace. App code also attaches listeners to `window`/`document`, while shared menus, dialogs, tooltips, and busy overlays append to `document.body`. Quire additionally embeds much of its editor CSS in `index.html`; Ledger's page is generated from `tools/ledger/build/`. Moving only the shell markup into a React component is not a valid implementation.

**Progress:** `public/common/core.js` provides reversible scoped lookup (`L.setDomRoot`), a persistent root registration (`L.mountDomRoot`), `L.domHost()`, and `L.createMountScope(root)` to own UI, events, and deferred callbacks. `common/ui.js` routes tooltip/menu/dialog/toast/busy layers to the active root; its `L.ui.mount(host)` lifecycle binds delegated handlers to the host, shares window handlers per mount, suspends standalone handlers while embedded, removes only layers owned by the disposed host, and reference-counts the shared window listener set so multiple roots do not duplicate blur/resize/aux-button handlers. The React editor host creates this scope before invoking engine mount and disposes it on unmount; async mount settlement disposes resources returned after unmount and reports live failures through `onMountError`. `EditorMountContext` carries an AbortSignal; the same-document legacy bridge ignores late open/save/draft completions after unmount and passes the signal to host file callbacks. Local open/save APIs and IndexedDB draft transactions accept the signal: file-input fallback listeners and nodes are removed on abort, native pickers reject promptly, writable file streams abort during writes where supported, and draft transactions abort. React chrome commands and direct-host engine listeners dispatch on the same editor host; no iframe, nested browsing context, or cross-window message protocol remains in the React runtime. App-level file-drop/keyboard/clipboard listeners and transient overlays have been progressively bound to the active root/mount scope, and browser regressions cover root restoration, per-host layer cleanup, listener/timer cleanup, asynchronous unmount cancellation, and native picker/draft cancellation. Direct-host styles, look settings, and language metadata are isolated from the embedding page, with production browser coverage for linked/inline CSS scoping and pseudo-locale application. The direct bridge still fetches/injects each app's complete fixed-ID legacy HTML shell and loads its classic scripts; `window.L`/`VO` and app state/hooks remain singletons, so simultaneous editor instances are not isolated. Not every script-evaluation/document/body dependency or app disposer has been removed. The bridge supports one editor at a time; this ticket remains in progress until shell/runtime ownership and genuine per-instance lifecycle are resolved.

**Suggested sequence:**

1. Extract each app's static editor shell and styles into buildable runtime assets, preserving the existing standalone HTML entry points. For Ledger, change the generator source and regenerate its output.
2. Replace unconditional auto-boot with an explicit app mount API that accepts a host element and returns an idempotent disposer; standalone pages call that same API on their root.
3. Introduce per-mount DOM lookup and overlay/event ownership, then remove global ID/body assumptions from the app and shared UI paths used by the editor.
4. Define and test engine namespace/state ownership for embedding. Do not silently promise multiple simultaneous editor instances until common `L`, `VO`, and app state are isolated.
5. Integrate each mount API in its React package, then remove the iframe bridge and cross-window protocol from suite/package code.

- [x] Lectern can initialize, mount into an explicit container, and dispose without assuming a page-global `#app` or taking ownership of `document.body`.
- [x] Standalone pages boot the same mount APIs and retain existing behavior.

- [x] Editor styles and document-level look/language settings do not leak into or get overwritten by the embedding host.
