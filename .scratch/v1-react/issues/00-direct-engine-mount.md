# 00: Direct editor-engine mount foundation

**What to build:** Replace the iframe-based React adapters for Quire, Ledger, and Lectern with explicit same-document mount/dispose APIs that render inside React-owned host containers.

**Blocked by:** None. This is a prerequisite for editor package and suite completion.

**Status:** ready-for-agent

**Architecture decision:** No iframe, nested browsing context, hidden iframe fallback, or cross-window postMessage bridge may remain in the React package/suite runtime. Keep the existing JavaScript document models, file-format readers/writers, calculation engines, and user-visible editing behavior. Refactor their bootstraps, DOM ownership, selectors, CSS boundaries, events, and lifecycle as required.

**Implementation notes:** The three current `A.init()` functions auto-run from classic scripts, query fixed IDs through `L.$`, and use the shared `window.L` namespace. App code also attaches listeners to `window`/`document`, while shared menus, dialogs, tooltips, and busy overlays append to `document.body`. Quire additionally embeds much of its editor CSS in `index.html`; Ledger's page is generated from `tools/ledger/build/`. Moving only the shell markup into a React component is not a valid implementation.

**Progress:** `public/common/core.js` provides reversible scoped lookup (`L.setDomRoot`), a persistent root registration (`L.mountDomRoot`), `L.domHost()`, and `L.createMountScope(root)` to own UI, events, and deferred callbacks. `common/ui.js` routes tooltip/menu/dialog/toast/busy layers to the active root; its `L.ui.mount(host)` lifecycle binds delegated handlers to the host, shares window handlers per mount, suspends standalone handlers while embedded, removes only layers owned by the disposed host, and reference-counts the shared window listener set so multiple roots do not duplicate blur/resize/aux-button handlers. The React editor host creates this scope before invoking engine mount and disposes it on unmount; async mount settlement now immediately disposes resources returned after unmount and reports live failures through `onMountError` without leaving unhandled rejections. `EditorMountContext` carries an AbortSignal; the legacy bridge stops frame/listener work, ignores late open/save/draft completions after unmount, and passes the signal to host file callbacks. Local open/save APIs and IndexedDB draft transactions accept the signal: file-input fallback listeners and nodes are removed on abort, native pickers reject promptly although the browser may keep their native UI open, writable file streams abort during writes where supported, and draft transactions abort. React chrome fallback commands dispatch directly to that editor's engine host, and the legacy bridge listens on that host instead of broadcasting commands through `window`; the existing iframe message channel remains only for the iframe-based runtime. All three apps' file-drop hints use the active host, Quire blue-background/ScreenTip classes and page shortcuts are scoped, Ledger's shortcut/lock-indicator listeners and Lectern's shortcut/clipboard listeners use the host, and app beforeunload/resize listeners use `L.addMountListener`. Drag tracking remains transiently bound for the duration of a gesture. Browser regression covers root restoration, nested UI roots, per-host layer cleanup, shared window listener refcounts, listener/timer cleanup, async mount late-resolution/rejection, late async-open cancellation, and native picker/draft transaction cancellation. Latest checks: core package build, typecheck, workspace package tests (19), and `git diff --check` pass. Crucially, global `L`/`VO` and each app's state/hooks are still singletons, and current app `A.init()` functions still require the complete fixed-ID HTML shell. No safe direct-engine package mount or full app disposer exists yet; shell extraction, app bootstraps, remaining document/body dependencies, iframe adapters, and genuine app cleanup remain.

**Suggested sequence:**

1. Extract each app's static editor shell and styles into buildable runtime assets, preserving the existing standalone HTML entry points. For Ledger, change the generator source and regenerate its output.
2. Replace unconditional auto-boot with an explicit app mount API that accepts a host element and returns an idempotent disposer; standalone pages call that same API on their root.
3. Introduce per-mount DOM lookup and overlay/event ownership, then remove global ID/body assumptions from the app and shared UI paths used by the editor.
4. Define and test engine namespace/state ownership for embedding. Do not silently promise multiple simultaneous editor instances until common `L`, `VO`, and app state are isolated.
5. Integrate each mount API in its React package, then remove the iframe bridge and cross-window protocol from suite/package code.

- [ ] Quire can initialize, mount into an explicit container, and dispose without assuming a page-global `#app` or taking ownership of `document.body`.
- [ ] Ledger can initialize, mount into an explicit container, and dispose without assuming a page-global `#app` or taking ownership of `document.body`.
- [ ] Lectern can initialize, mount into an explicit container, and dispose without assuming a page-global `#app` or taking ownership of `document.body`.
- [ ] Standalone pages boot the same mount APIs and retain existing behavior.
- [ ] Shared engine services and app state have an explicit instance/lifecycle boundary suitable for embedding; no app requires an iframe to isolate globals.
- [ ] Event listeners, timers, observers, dialogs, and overlays created by an app instance are removed or closed by its disposer.
- [ ] Editor styles and document-level look/language settings do not leak into or get overwritten by the embedding host.
- [ ] React package and suite integration tests prove all three editors mount in the same document with no iframe elements and can unmount cleanly.
- [ ] Existing standalone legacy entry points, UI behavior, file compatibility, and PWA behavior remain functional.
