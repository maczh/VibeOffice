# React editor packages

In React-host mode, the shared legacy host adapter exposes the package IDs `wordx`, `excelx`, and `pptx` for file-type resolution, template selection, editor attachment, navigation, and the active engine's `L.APP_ID`/`L.APP_NAME`; switching packages updates that identity before the app initializes. Classic web and desktop launches retain their established route IDs for compatibility. The shared in-app New gallery and transient drag-cursor styles are scoped to the mounted editor root, and editor startup leaves the host favicon unchanged.

Direct-host language initialization and DOM translation are likewise scoped to the mounted editor root; the embedding document keeps its own `lang` attribute and existing text.

The shared React `EditorDragLayer` owns direct-host drag state and pointer/keyboard/mouse listeners, including threshold tracking, pointer capture, cursor scoping, Escape/undo cancellation, and second-button suppression. The legacy `ui.drag()` API remains the synchronous engine-facing adapter and returns the same drag data; `ui.dragging()` and `ui.dragCancel()` delegate to the mounted layer. Classic pages retain their standalone drag fallback.

Direct-host command search UI and its typed command catalog are package-owned: `CommandSearch` renders the accessible input/list and emphasizes matched label text with React text nodes, and `installCommandSearchService` is installed at the legacy search script's dependency slot before that mixed DOM/service module is skipped. `public/common/command-match.js` owns the single shared synonym, tokenization, typo-scoring, and result-limit implementation used by both this React service and classic `public/common/search.js`; it extends the existing `VO` object without replacing Suite services. Search retains placement, enabled-state, and recent-command behavior across menu-bar and Ribbon layouts. The legacy Scout action resolves its search target through a scoped compatibility adapter to this React-owned input; production coverage activates Scout's “Find a command by name” choice and verifies focus reaches the React input. Classic standalone pages continue loading `public/common/search.js` as their fallback.

The shared `EditorUiContentLayer` owns direct-host field labels and group legends/content containers in React. `ui.field()` and `ui.group()` still provide stable DOM-compatible hosts and synchronously attach engine controls/children so adjacent React adapters can register before insertion; the React layer renders translated labels, moves the original nodes into its content slots, preserves label/control association and releases those nodes on unmount. Classic pages retain the original `ui.js` field and group constructors.

The shared `AppearanceFields` component owns the staged Theme/Language controls used by Wordx, Excelx, and PPTX Options dialogs. Each app supplies its current catalog, translation function, and change adapter; the shared component owns the accessible labels/selectors while each engine retains its existing apply/cancel transaction.

Each direct engine package renders its fixed-ID root and static app shell as React-owned DOM before the legacy engine modules mount; disposal leaves that shell to React reconciliation and preserves sibling content managed by the embedding application.

The shared editor frame isolates app-owned React layers with an error boundary. Embedded hosts may provide `renderError` with localized fallback content and `onRenderError(error)` for reporting; a layer failure leaves the document-engine host outside the boundary.

Each editor package accepts an optional `onTitleChange(title)` callback. Embedded editors report document-title updates without mutating the embedding page's title; the suite opts in and updates its own browser title. The host owns its page title and favicon when no callback is provided.

In Wordx direct-host mode, the Outline heading-marker pointer listener, Find/Replace Enter-key routing, and the editor root's before-input, keyboard, composition, clipboard, drag/drop, mouse and context-menu events are owned by React effects; the classic standalone page keeps its legacy event handlers. Inline-object and floating-object resize/rotate handles both delegate pointer-down through the React document interaction bridge, with the existing editor/drawing drag services retaining geometry and commit behavior. The task-pane navigation header and pane-selector menu are React-only in direct-host mode, with no hidden classic controls/listeners; the selector supports radio state, arrow/Home/End navigation, Escape and focus restoration, while its legacy Recent Files recovery route is omitted because the suite provides draft recovery separately. The app-level shortcut/modifier key handlers, file drag/drop and hint, document-map splitter, window resize, document scrolling, selection-complete brush release, and complete AutoShape pointer gesture lifecycle (including Shift constraints, the React-rendered preview ghost, pointer cancellation, and Escape) are owned by React effects with unmount cleanup; the existing drawtool adapter commits the shape into document history, while classic pages retain the legacy drag handler. Print Preview page-click zoom is likewise attached by the React toolbar lifecycle in direct-host mode and cleaned up on view exit. AutoShape, object-shadow, table-insertion-grid, column-picker, page-background, highlight-palette, border-command, border-style, border-weight, drawing-object line-weight, dash-style, arrowhead, Undo/Redo history, and Print Preview multi-page menu contents are React-rendered in direct-host mode; their selection actions still delegate to the existing editor transactions. The direct-host status bar cells are rendered only by React from an engine status snapshot; the classic path still builds its original DOM. The React status message portal remains the only status-bar DOM slot created by the direct-host engine adapter. Toolbar visibility for all three editors is now derived from each app's visibility snapshot and applied by the shared React toolbar lifecycle, including empty-row collapse; classic pages retain engine-side visibility updates. Document mutation, layout and navigation/model operations remain engine-backed.

The shared React toolbar renders app-provided command, split and drop controls as React buttons, preserving live command state and dispatching existing engine commands/menu callbacks from the button anchor; no app-provided `ui.tbButton()` DOM nodes or native click listeners remain in the three React toolbars. Ribbon contextual/task-pane construction and the view-bar/IntelliArt tool areas explicitly request DOM controls because those legacy renderers still consume actual elements; classic toolbar construction is unchanged. Production browser coverage asserts that React toolbars contain no unowned legacy buttons, opens populated dropdown menus in all three editors, and exercises the PPTX contextual Ribbon panel.

The shared React Paper 2016 Ribbon preserves responsive group folding in narrow hosts: groups fold from the right, the folded group button opens its controls in a positioned React popup, outside click and Escape dismiss it, Escape restores focus, and ResizeObserver unfolds groups when the host widens. Classic Ribbon pages retain their existing fit behavior.

## Wordx source-module disposition


This is an ownership inventory, not a claim that migration is complete. The React packages own their static engine shells in `wordx/src/engine-shell.tsx`, `excelx/src/engine-shell.tsx`, and `pptx/src/engine-shell.tsx`; direct-host mounts now load the Vite-generated runtime manifest instead of fetching legacy HTML. The compatibility loader still loads 10 of the 34 files under `public/quire/js/`; it skips `ribbon.js`, `templates.js`, `portions.js`, `drawtool.js`, `outline.js`, `autocorrect.js`, `rulers.js`, `omml.js`, `mailmerge.js`, `find.js`, `spell.js`, `htmlio.js`, `markdown.js`, `mdio.js`, `rtf.js`, `docx-read.js`, `docx-write.js`, `fields.js`, `commands.js`, `ops.js`, `dmodel.js`, `drawing.js`, `preserve-drawing.js`, and `preserve.js`, registering their package-owned Wordx implementations instead. Document, format, and layout services may remain imperative; every UI and interaction surface must move to React. “Partial” means some React ownership exists while legacy UI/coordination remains.

The React packages render each app's static shell into a React-owned host and mount the existing engine in the same document; no iframe or cross-window messaging is used. The Vite runtime plugin derives a per-app `runtime.json` asset manifest from the compatibility HTML at dev/build time. Direct React mounts fetch that manifest (ordered scripts plus linked and inline styles), scope its styles, load the classic modules, then call `L.app.mount(host)`; they do not fetch or parse the legacy HTML document. Classic standalone pages still use their original HTML entry points. A per-script hook lets packages install typed compatibility services at the dependency slot of a skipped classic module; the script loop checks the mount AbortSignal around each hook and aborts loading on disposal. Each app returns an idempotent disposer; standalone React pages use the same mount API with `document.body`. Fixed engine IDs, `window.L`, `window.VO`, command registries, and app state remain global. Consequently, only one legacy editor engine can be mounted in a document at a time; the suite unmounts the active editor before switching. This direct mount is an integration seam, not completion of the requested React migration: many app and shared UI modules still execute from `public/` as classic JavaScript.

The `@vibeoffice/core` exports include `RemoteStorageProvider`, `createWebDavProvider`, and `createUrlReadProvider`. A host can implement `RemoteStorageProvider` for custom POST endpoints or S3; signing, listing, and authentication remain the host's responsibility. Pass host-owned file pickers as `onOpenFile`/`onSaveFile` callbacks. `createRemoteFileCallbacks` forwards the editor mount's `AbortSignal` to host pickers and provider operations, uses the opened remote revision for ordinary Save, and treats Save As as a separate destination selection so it does not overwrite the source. A destination revision, when available, is passed to the provider for a conditional write. The WebDAV credential callback is invoked for each operation and credentials are not stored by the provider. Revisions are represented as ETags; conditional writes use `If-Match`, and HTTP 409/412 responses report a revision conflict. Filesystems or APIs without revisions cannot protect against concurrent changes.

For an embedded custom provider, keep the user's listing choice in the host and adapt it to the editor callbacks:

```tsx
import { createRemoteFileCallbacks } from '@vibeoffice/core';
import { ExcelxEditor } from '@vibeoffice/excelx';

const remote = createRemoteFileCallbacks(myProvider, chooseRemoteFile, chooseRemoteDestination);
<ExcelxEditor
  engine={{ url: '/excelx/' }}
  onOpenFile={remote.onOpenFile}
  onSaveFile={remote.onSaveFile}
/>
```

`myProvider` implements the typed list/read/create/save contract. A host that uses S3 supplies its own short-lived signed requests and never passes AWS credentials to the editor. The suite's Start Center also offers Open URL and WebDAV; build it with `VITE_REMOTE_ORIGINS=https://dav.example,https://files.example` so both the provider origin allowlist and generated CSP are explicit.

For remote access, the embedding application's Content Security Policy must list only the intended service origins in `connect-src`, and the remote service must allow the app origin in its CORS policy. The URL reader is read-only. WebDAV uses browser `PROPFIND`, `GET`, and `PUT`; the server must allow those methods and the `Authorization`, `If-Match`, and `If-None-Match` request headers, and expose `ETag` to browser JavaScript. Do not place long-lived secrets in package configuration or browser storage.
