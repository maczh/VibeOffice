# React editor packages

The Wordx Cross-reference dialog body is React-rendered: reference type, available item and representation, hyperlink, and above/below options are controlled in React; the existing field insertion engine remains responsible for document edits.
The Wordx Language dialog body is React-rendered, including its language catalog, spelling/grammar exclusion, and automatic-detection controls; selected language and proofing options continue through the existing editor-format API.
The Wordx Drop Cap dialog body is React-rendered for position previews, font, line count, and distance; the existing paragraph-splitting and drop-cap formatting operation remains engine-owned.

The Wordx Mark Index Entry dialog body is React-rendered for main/subentries, current-page or cross-reference options, and bold/italic formatting; the existing index-field and Mark All operations remain engine-backed.

The Wordx Field dialog body is React-rendered for category/name browsing, field code editing, format/date-picture choices, update-preservation and result preview; field parsing and insertion/update remain engine-backed.

The Footnote and Endnote dialog body is React-rendered for location, number format, custom mark, starting number and restart rules; note settings/insertion remain engine-backed, with conversion handed to the existing conversion dialog.

The Wordx Diagram Gallery previews and six preset selectors are React-rendered; diagram geometry and insertion remain in the drawing engine.

The Wordx Find and Replace search/replacement input rows, Find-tab Highlight All/search-scope controls, expanded Search Options (direction, case, whole-word, wildcard, sounds-like, and all-word-forms), No Formatting/Format/Special actions, and accessible More/Less toggle are React-rendered and continue feeding the legacy matcher, criteria model, and replacement operations; Go To is also React-rendered. The formatting/special-character menus themselves and other legacy body controls remain in migration scope.

In Wordx direct-host mode, the Getting Started pane (without Recent Files), New Document task-pane body, Help body, Basic File Search pane, Clip Art pane, Office Clipboard pane, Styles and Formatting pane, Reveal Formatting pane, Protect Document pane, Research pane, six-step Mail Merge wizard, task-pane navigation header, Reviewing Pane, Document Map, page-thumbnail rail, status bar, Go To tab and Find/Replace controls/options, Sort and Sort Text dialog body, Table AutoFormat style list/preview/special-format controls, Tabs, Change Case, Text Direction, and Theme dialog bodies/previews, Bookmark dialog body, Insert Object dialog body, Equation dialog body, Break dialog body, Date and Time dialog body, Page Numbers and Page Number Format dialog bodies, Insert Cells, Delete Cells and Split Cells dialog bodies, Insert Table, Convert Text to Table, Convert Table to Text and Formula dialog bodies, Reading Layout toolbar, and Print Preview toolbar are React-rendered. Creation, open/help/style/mail-merge navigation, search selection, artwork insertion, clipboard history, paste, Paste All, Clear All, applying formatting, opening formatting dialogs, protection confirmation, thesaurus lookup, document search, merge actions, pane Back/Forward/Home/menu/Close, review selection/comment editing, heading navigation, thumbnail navigation, Go To navigation, bookmark creation/deletion/selection, existing-file selection, equation symbols and insertion, page/column/wrapping and section-break actions, date-format preferences and field/text insertion, page-number position/alignment/first-page controls, numbering format/chapter/start settings, cell insertion/deletion/splitting directions, table dimension/AutoFit/style and remembered-size handling, text/table separators and conversion options, sorting paragraphs/table rows, table style preview and application, adding/removing/alignment/leader/default-spacing of tab stops, case transformation, text direction for text boxes/table cells, applying document themes, formula functions/bookmark references/number formats and field insertion, status actions, Reading Layout commands, and preview controls delegate to existing editor APIs. Page artwork remains engine-generated and is cloned as non-editable thumbnail content. Classic Wordx pages retain their original renderers.

The browser workspace is built from `commonx`, `wordx`, `excelx`, and `pptx`. The editor packages expose `WordxEditor`, `ExcelxEditor`, and `PptxEditor`; React and React DOM are peer dependencies. `npm run build` emits JavaScript declarations and `style.css` artifacts under each package's `dist/`. `npm run build:apps` emits independently hosted React shells plus the existing static document engine under each package's `standalone/` directory. The React suite serves its editor engines at `/wordx/`, `/excelx/`, and `/pptx/`. Serve the contents of a standalone directory at its origin root; no VibeOffice API server is required.

The React packages mount the existing editor engine into a React-owned host in the same document; no iframe or cross-window messaging is used. The adapter fetches the same-origin legacy shell and its ordered classic scripts, scopes its styles, and then calls `L.app.mount(host)`. Each app returns an idempotent disposer; standalone pages use the same mount API with `document.body`. The full legacy shell and fixed engine IDs are still required, and `window.L`, `window.VO`, command registries, and app state remain global. Consequently, only one legacy editor engine can be mounted in a document at a time; the suite unmounts the active editor before switching. This direct mount is an integration seam, not completion of the requested React migration: many app and shared UI modules still execute from `public/` as classic JavaScript.

Example package use:

```tsx
import { WordxEditor } from '@vibeoffice/wordx';
import '@vibeoffice/wordx/style.css';

export function DocumentEditor() {
  return <WordxEditor />;
}
```

The final host page must also load the shared look variables (`/common/looks.css`) before the editor stylesheet, and serve the selected engine assets plus `/common/`, `/fonts/`, and `/icons/` from the same origin. Standalone Vite entries include these shared look styles and runtime assets.

`ExcelxEditor` and `PptxEditor` have equivalent APIs. The host may provide `onOpenFile`, `onSaveFile`, `onDraftSaved`, `onEngineReady`, and a `DraftStore`. The default local adapter uses the File System Access API when available and otherwise downloads saves. Crash drafts use a dedicated `vibeoffice-react-drafts` IndexedDB database; the legacy Recent Files database is not read or deleted in React-host mode.

The `@vibeoffice/core` exports include `RemoteStorageProvider`, `createWebDavProvider`, and `createUrlReadProvider`. A host can implement `RemoteStorageProvider` for custom POST endpoints or S3; signing, listing, and authentication remain the host's responsibility. Pass host-owned file pickers as `onOpenFile`/`onSaveFile` callbacks. The WebDAV credential callback is invoked for each operation and credentials are not stored by the provider. Revisions are represented as ETags; conditional writes use `If-Match`, and HTTP 409/412 responses report a revision conflict. Filesystems or APIs without revisions cannot protect against concurrent changes.

For an embedded custom provider, keep the user's listing choice in the host and adapt it to the editor callbacks:

```tsx
import { createRemoteFileCallbacks } from '@vibeoffice/core';
import { ExcelxEditor } from '@vibeoffice/excelx';

const remote = createRemoteFileCallbacks(myProvider, chooseRemoteFile, chooseRemoteDestination);
<ExcelxEditor
  engine={{ url: '/excelx/' }}
  onOpenFile={remote.onOpenFile}
  onSaveFile={remote.onSaveFile}
/>
```

`myProvider` implements the typed list/read/create/save contract. A host that uses S3 supplies its own short-lived signed requests and never passes AWS credentials to the editor. The suite's Start Center also offers Open URL and WebDAV; build it with `VITE_REMOTE_ORIGINS=https://dav.example,https://files.example` so both the provider origin allowlist and generated CSP are explicit.

For remote access, the embedding application's Content Security Policy must list only the intended service origins in `connect-src`, and the remote service must allow the app origin in its CORS policy. The URL reader is read-only. WebDAV uses browser `PROPFIND`, `GET`, and `PUT`; the server must allow those methods and the `Authorization`, `If-Match`, and `If-None-Match` request headers, and expose `ETag` to browser JavaScript. Do not place long-lived secrets in package configuration or browser storage.

In the PPTX package, speaker notes, the normal slide-thumbnail rail, Outline, Slide Sorter, Notes Page, Print Preview toolbar, slide-show navigation/menu controls, numeric Go to Slide prompt, black/white screen and end-of-show overlays, Rehearse controls, and navigation chrome for both side panes are React-owned. The notes layer forwards input into the engine's history/model adapter; the slide rail uses the engine's slide renderer and command methods for selection, drag reorder, context menus, and transition previews. Slide Sorter retains engine-backed selection, multi-selection, reorder, context menus, transition preview and keyboard focus. Notes Page retains the engine-rendered slide preview and notes history/model updates. Outline uses the existing title/body row model, outline history, keyboard demote/promote/new-row behavior, slide synchronization and delayed model commit. It defers React refresh while contenteditable rows are browser-mutated, then rebuilds from the committed model when leaving the pane. Print Preview's print/format/page-count/color/frame/PDF/close controls are React-rendered, while page layout and slide artwork remain in the presentation engine. Slide-show stage rendering, transitions, keyboard navigation, ink and timing stay in the presentation engine; React renders the Previous/Next, menu triggers, Go to Slide prompt, black/white screen and end-of-show overlays, and Rehearse next/pause/resume/elapsed/total/repeat controls. Engine timers publish updates to React, and the existing save-timings confirmation remains unchanged. The Slides/Outline pane tabs and task pane's Back, Forward, Home, title menu, and Close controls call the existing engine APIs. The Getting Started, New Presentation, searchable Help, Clip Art, Slide Design, Color Schemes, Animation Schemes, Slide Layout, Slide Transition, Custom Animation, and Clipboard task-pane bodies are React-rendered; they invoke the same open/new/sample/help/design/animation/AutoContent/photo-album operations, search the existing built-in clip-art library and insert through the presentation engine, or apply/import presentation designs, palettes, animation definitions, slide layouts, transitions, and custom effects through engine APIs. Effect-specific options still use the existing dialog and engine model. Clipboard history, paste, paste-all, and clear continue to use the presentation engine's data and commands. Other task-pane feature bodies still use their engine renderers. The classic page keeps its original notes, pane tabs, task-pane header/body, thumbnail, Outline, Slide Sorter, Notes Page, Print Preview and slide-show controls when no React layer is mounted. Remaining presentation UI is not yet React-owned.

The shared React editor chrome provides New/Open/Save, command search, look/language selectors, and the About modal for every package. The React command search uses the mounted engine's catalog and matcher, including keyboard selection and Alt+Q. Direct-host About, message-box, prompt, password, hyperlink, compatibility, toast, busy-progress, tooltip, color-picker, menu-bar, command-menu, generic-dialog, Ribbon, toolbar, status-message, editable-combo, native-select, numeric-spinner, checkbox, radio, tab-header, shared button-label, field-label, and group-legend requests are rendered by shared React components. The Ribbon's tab strip, group layout, Quick Access Toolbar, contextual tabs, collapse behavior, ordinary command buttons, split/drop button structures, and editable combo inputs are React-owned; app menu callbacks still supply their content to the shared React menu layer. Common UI button labels/markup are React-rendered inside the legacy-created native button so the existing DOM reference, callbacks, attributes, and imperative content updates remain intact. `ui.field()` labels and `ui.group()` legends are React-rendered content in their existing semantic native elements; field IDs and group children remain supplied by the engine. Wordx's reusable feature list-box option rows are rendered by a Wordx-package React layer, retaining the existing value selection, `get/set/setItems`, double-click callbacks, and filtering behavior; its optional text input and containing dialog composition remain legacy DOM. In direct-host mode, the Wordx Help body (topic search and keyboard-shortcut list), Basic File Search pane (input, results, match count and selection handoff), and Clip Art pane (search, result buttons and insertion handoff) are React-rendered from the existing localized Help/clip-art catalogs and document-search engine; classic Wordx pages keep their original renderers. Excelx's formula-bar toolbar, Name Box, visible formula editor, worksheet tab rail/items, sheet-navigation arrows, and tab-area resize grip are rendered by an Excelx-package React layer. The sheet tab React controls retain active/group selection, inline rename, context menu, drag-to-reorder/copy behavior, and tab-area resize/cancel behavior through workbook and UI operations exposed by the legacy controller. Visually hidden legacy fields remain as temporary adapters; React forwards formula-bar value and keyboard changes through the editor contract and Name Box input through the existing go-to command, while the calculation engine still owns formula parsing, commit/cancel behavior, named-range resolution, sheet model updates, and cell evaluation. The worksheet tab model and its commands remain in the classic app controller; the drag semantics for its resize grip still use the existing engine drag helper. The generated classic Excelx page retains native formula-bar/Name Box controls, sheet tabs, and navigation arrows when not mounted through the React package. PPTX's speaker-notes editor is rendered by a PPTX-package React layer, forwarding edits into the legacy notes history/model adapter and refreshing when the selected slide changes; classic PPTX pages continue to show their original notes editor. Combo values, options, notes, previews, edit callbacks, and form-control callbacks remain backed by the existing engine APIs. Checkbox/radio labels and inputs, native select options, spinner controls, and tab headers are React-rendered while compatibility references such as `.input`, `.get()`, `.set()`, `.setDisabled()`, and `tabs.select()` continue to be exposed. Tab panel contents still come from existing engine-created DOM. App-specific `make()` controls continue in explicit legacy DOM slots. Toolbar rows and ordinary command buttons are React-owned with live enabled/checked state; app-provided DOM controls are moved into explicit React slots. Status text content is rendered by React, but Wordx/PPTX still compute status data in the legacy app modules. The generic dialog preserves the legacy synchronous element/Promise/callback API by moving its feature-specific body DOM into a React-owned modal shell; its title bar, focus handling, drag behavior, and buttons are React-owned, but each feature's body is not yet a React component. About preserves app text/icon/version, prompts preserve entered text or cancellation, protected-file dialogs keep password input private, hyperlink interstitials show/copy without navigation, compatibility decisions retain exact pending-loss records, and color selection continues to use the engine's color model/callbacks. Shared React overlays portal into the scoped engine root so they retain each app's existing Office styles without leaking those styles to an embedding page. The suite Start Center uses React dialogs for URL opening, WebDAV browsing, Save As destination selection, and remote revision-conflict choices. New creates a blank document directly; returning to Create File asks the engine to resolve unsaved changes and keeps the editor mounted if the user cancels. Legacy custom `make()` controls, DOM-based app controls, custom DOM menu contents, feature-specific dialog bodies, and most shared/app UI are not yet React components. The standalone packages include the existing app resources and service worker. The Vite configuration is a build/development tool, not a production runtime dependency.
